- (decision) AD-1 Paradigm: Clean/layered architecture, 4-project solution (Api, Application, Domain, Infrastructure). Dependency direction: Api->Application->Domain; Infrastructure->Domain (implements Domain/Application interfaces); Api wires Infrastructure only at composition root (Program.cs). User-chosen over single-project layout for stronger compiler-enforced boundaries and its own ADR-worthiness.
- (decision) AD-2 Repository + Unit of Work: interfaces (IProductRepository, IUnitOfWork) live in Domain/Application, implementations in Infrastructure. Binds FR-2, FR-7. Prevents Api/Application from depending on DbContext directly.
- (decision) AD-3 DTO boundary: Domain entities never cross the Api boundary; request/response DTOs live in Application. Binds FR-3.
- (decision) AD-4 DI lifetimes: DbContext + repositories = Scoped; app services = Scoped by default; only framework-provided singletons (logging, config) are Singleton. Binds FR-2, FR-9. Note: FR-2/FR-9 require deliberately reproducing a scoped-into-singleton violation once for the postmortem -- that is a scoped, documented, one-time exception for the incident artifact, not a standing exception to this rule.
- (decision) AD-5 Token storage: JWT issued as httpOnly, Secure, SameSite cookie by the login endpoint; React never reads or stores the raw token; mutating requests carry a CSRF/anti-forgery token validated server-side. User-chosen (httpOnly cookie) over localStorage per XSS tradeoff. Binds FR-4, FR-5. Feeds PRD ADR-003.
- (decision) AD-6 Correlation ID: middleware assigns a correlation id per request (header X-Correlation-Id, generated if absent) and attaches it to the ILogger scope for the request lifetime. Binds FR-1 NFR, FR-9 (postmortem timeline accuracy).
- (decision) AD-7 Frontend resilience: retry-with-backoff (exponential, max 3 attempts) only on network errors and 5xx responses; never retried on 4xx. Binds FR-5.
- (assumption) [ASSUMPTION] AD-8 Validation strategy: Data Annotations on DTOs + [ApiController] automatic 400 responses, no FluentValidation dependency -- simpler paved path for this scope. Binds FR-3.
- (assumption) [ASSUMPTION] AD-9 Mapping strategy: manual mapping via extension methods (ToDto()/ToEntity()), no AutoMapper dependency -- compiler-checked, and the manual code itself becomes a teachable comment-bearing artifact. Binds FR-3, FR-7 (feeds PRD ADR-002).
- (assumption) [ASSUMPTION] AD-10 Category deletion: reject with 409 Conflict when existing Products reference the Category; no cascade delete -- avoids silent data loss, resolves PRD FR-1's open cascade question and addendum note.
- (version) Verified via web search (2026-08-18): .NET 10 is current LTS (supported to Nov 2028); .NET 8 also still LTS (to Nov 2026) but .NET 10 is the correct pick for a new build. EF Core version tracks .NET major (EF Core 10.x for .NET 10).
- (version) Verified via web search (2026-08-18): React 19.x is current major (latest patch ~19.2.8, July 2026). Some sources flag React 18 as the 'safer' production LTS-style pick, but for a new learning/portfolio build React 19 (current) is appropriate.
- (version) Frontend build tool: Vite (React + TS template) chosen over Create React App, which is deprecated -- Vite is the current well-known paved-path starter for a React SPA in 2026.
- (version) xUnit and Moq versions not individually web-verified -- low-risk, fast-moving minor packages; spine notes 'latest at scaffold time' rather than a stale pin.
- (direction) Deployment & environments: explicitly out of scope per PRD 6.2 (no live/hosted deployment required for v1) -- local dev only (dotnet run + Vite dev server against LocalDB/SQL Server Developer edition). Recorded so the operational envelope isn't silently skipped.
- (direction) Deferred: exact xUnit/Moq/EF Core patch versions (pin at scaffold time); CI/CD pipeline (no deployment in scope); Angular track (PRD 6.2, parked for a possible v2); multi-tenant/roadmap horizons (FR-10, EM-track content, not this altitude's concern).
- (decision) Consistency convention -- error envelope: all 4xx/5xx API error responses use RFC 7807 ProblemDetails (ASP.NET Core's built-in shape), produced by [ApiController] automatically for validation and by a global exception-handling middleware for unhandled exceptions. Binds FR-3, FR-1.
- (assumption) [ASSUMPTION] IDs: int identity primary keys for Product/Category (not GUID) -- simplest for this scope. Dates: DateTime stored/serialized as UTC ISO 8601 (System.Text.Json default).
- (decision) Consistency convention -- naming: PascalCase C# types/namespaces, camelCase JSON payload properties (System.Text.Json default), lowercase-plural kebab API routes (/api/products), PascalCase React components, camelCase TS variables/props.
